# 03 · 角色人生轨迹系统 —— 数据结构与运转机制

> 版本 0.1 · 本作灵魂系统的落地设计
> 目标：30 个角色因环境与事件改变人生方向、职业、爱好，玩家可影响但不可控制

---

## 一、角色数据结构

```jsonc
{
  "id": "chr_012",
  "name": "阿依莎",
  "culture": "sogdian",          // 文化圈：han / sogdian / persian / kucha / khotan / nomad ...
  "age": 19,
  "gender": "f",

  // ── 四个人生维度 ──────────────────────────
  "personality": {                // 性格五维，0~100，缓慢变化
    "courage": 35,                // 勇气：冒险 vs 求稳
    "curiosity": 88,              // 好奇：求新 vs 恋旧
    "faith": 20,                  // 虔诚：信仰驱动 vs 现世驱动
    "sociability": 70,            // 交际：合群 vs 独行
    "ambition": 55                // 野心：成名立业 vs 岁月静好
  },
  "hobbies": ["music_pipa", "stargazing"],   // 爱好标签，事件可增删
  "belief": { "type": "zoroastrian", "intensity": 20 },  // 信仰及强度
  "bonds": [                      // 牵挂：转折点的"锚"，也是"重逢钩子"的来源
    { "type": "person", "target": "chr_003", "kind": "family",  "strength": 80 },
    { "type": "place",  "target": "city_samarkand",  "kind": "hometown", "strength": 60 },
    { "type": "item",   "target": "itm_mothers_lute", "kind": "keepsake", "strength": 90 }
  ],

  // ── 职业与能力 ──────────────────────────
  "career": {
    "current": "merchant_apprentice",
    "history": [                  // 人生履历，结算与"文书残片"彩蛋直接读这里
      { "year": 1, "career": "merchant_apprentice", "cause": "birth_family" }
    ]
  },
  "skills": { "trade": 3, "music": 2, "craft": 0, "guide": 0, "medicine": 0 },
  "languages": ["sogdian", "han_basic"],

  // ── 状态与经历 ──────────────────────────
  "mood": 65, "health": 90,
  "lifeFlags": [],                // 经历标记，如 "sandstorm_survivor"、"heard_kucha_music"
  "location": "caravan",          // caravan / city_xxx / departed
  "relations": { "chr_007": { "affinity": 40, "tension": 10 } }  // 队内羁绊/矛盾
}
```

**设计要点**
- `personality` 是转折掷骰的权重来源，`lifeFlags` 是转折的开关，`bonds` 是转折的方向盘
  （人会往牵挂的方向转折：想家的回乡，恋人的追随，执念的守护）。
- 一切转折都写进 `career.history`，它就是这个角色的"传记"，年末回顾和结算彩蛋零成本生成。

## 二、人生转折点：规则表驱动

转折不是脚本剧情，而是**规则表 + 掷骰**，保证 30 个角色能涌现出不重样的人生。

```jsonc
{
  "id": "tp_sandstorm_to_faith",
  "name": "劫后皈依",
  "trigger": {
    "requiredFlags": ["sandstorm_survivor"],       // 必须有的经历
    "personality": { "faith": ">40", "courage": "<50" },
    "context": { "nearLocation": "temple_any" }     // 情境条件：附近有寺庙
  },
  "weight": 30,                    // 基础权重，与性格匹配度相乘
  "cooldown": "life_once",         // 一生一次 / 每 N 年
  "outcomes": [{
    "careerChange": "monk",
    "beliefChange": { "type": "buddhist", "intensity": "+50" },
    "departure": { "joinLocation": "nearest_temple" },   // 离队，定居于最近寺庙
    "echoHooks": [                 // ★ 命运回响：给未来埋的钩子
      { "when": "player_visits_location", "event": "reunion_monk_shelter" }
    ],
    "storySeed": "story_survivor_monk"   // 同时生成一条可收集、可传播的故事！
  }],
  "playerInfluence": {             // 玩家可推一把，但只是改概率
    "options": [
      { "id": "persuade_stay", "text": "劝他留下", "check": "sociability", "effect": { "weight": "-40", "tensionWithPlayer": "+15" } },
      { "id": "fund_temple",   "text": "资助他修行", "cost": 200, "effect": { "echoBonus": "+1", "reputationBuddhist": "+10" } },
      { "id": "let_go",        "text": "送他一程",  "effect": { "moodAll": "+5", "storyQuality": "+1" } }
    ]
  }
}
```

**触发管线（每季一次"人生结算"阶段）**

```
世界/旅途事件发生 ──► 给在场角色打 lifeFlags
                            │
        季末扫描：每个角色 × 转折规则表，筛出满足 trigger 的候选
                            │
        权重掷骰（基础权重 × 性格匹配 × bonds 拉力 × mood 修正）
                            │
     ┌── 未触发：什么都不发生（大多数季度如此，转折应当稀有而珍贵）
     └── 触发：若角色在商队/玩家在场 → 弹"人生卡片"给玩家三选一影响
                            │
        写入 career.history ──► 执行 outcomes（转职/离队/爱好变化…）
                            │
        注册 echoHooks 到目标城市/路线 ──► 生成 storySeed 进入故事池
```

**频率控制**：全局每年转折数软上限（如 2~4 起），用"戏剧点数"配额防止同年集体转职；
商队成员权重加成 ×1.5（玩家身边的人故事密度更高）。

## 三、转折规则的内容矩阵（首批 20 条的规划框架）

| 触发类别 | 示例规则 | 改变什么 |
|----------|----------|----------|
| 天灾劫后 | 沙暴幸存→皈依 / 雪崩获救→拜救命恩人为师转职向导 | 职业+信仰 |
| 文化触动 | 听龟兹乐→弃商学琴 / 见敦煌壁画→迷上绘画（新爱好） | 职业/爱好 |
| 牵挂拉力 | 家乡城市衰败→回乡照料 / 恋人定居某城→随之离队 | 去向 |
| 世事变迁 | 战乱失业的铁匠加入商队 / 商路萧条的向导改行说书 | 职业 |
| 队内羁绊 | 与染匠同行百日→织工悟出新配方并转职（联动合成系统） | 职业+配方 |
| 岁月自然 | 老向导退休定居，收徒（徒弟成为可招募新角色） | 世代交替 |

每条规则都要求：**至少产出一个 echoHook 或 storySeed**——
转折不是角色的终点，而是世界后续内容的生成器。

## 四、离场角色的简化模拟与重逢

角色 `departure` 后进入离场池，降级为轻量状态机，**每年更新一次**：

```
安顿中 → 立业（按新职业+性格掷骰：开店/收徒/成名/潦倒）
       → 变故（小概率：迁居/婚嫁/离世——离世前必留一封信或一件遗物给玩家）
```

- 每次更新只改 3 个字段：`status`、`location`、追加一条 `history`，成本可忽略
- **重逢钩子**：玩家进入其所在城市时按 `echoHooks` 触发重逢事件——
  重逢内容由"离开时的关系 + 离场后的 history"拼装，所以每次重逢都不一样
- 离场角色可以被**重新招募**（需满足其新牵挂的条件，例如帮她的乐坊找到继任者）

## 五、玩家角色的人生

玩家（商队主人）不豁免于这套系统：爱好、声望、信仰同样被事件塑造，
结算时玩家自己的 `career.history` 就是"这一局你活成了什么样的人"——
五维评分之外的定性总结（"你是一位痴迷星象、被于阗人视为友邦的乐痴商人"）。

## 六、最小原型验证清单（P0）

- [ ] 3 座城（敦煌—楼兰—于阗）+ 5 种货 + 价差贸易 + 15 年时钟
- [ ] 6 个角色（商队 4 + NPC 2），完整数据结构
- [ ] 8 条转折规则（每个触发类别至少 1 条）
- [ ] 人生卡片 UI 流程：触发 → 三选一 → 结果播报
- [ ] 1 条完整的命运回响链：离队 → 离场模拟 → 重逢
- [ ] 年末"年话"回顾（读 career.history 自动生成）

**验证标准**：不看数值面板、只看角色的人生变化，测试者是否愿意再玩一年？
